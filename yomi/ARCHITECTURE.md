# Yomi website architecture

Yomi uses one shared site shell and one route-based language model.

## Language contract

- Product pages use `/yomi/` for English and `/yomi/zh-tw/` for Traditional
  Chinese. The localized home is generated from the English source document by
  `scripts/sync-yomi-home-locale.mjs` so their structure cannot drift.
- Search-focused guides also use separate canonical URLs:
  `/yomi/line-mcp/` and `/yomi/zh-tw/line-mcp/`. Their language controls always
  navigate to the reciprocal route; guide content must not use `data-t` swaps.
- Every localized page family must publish reciprocal `hreflang` entries for `en`,
  `zh-Hant-TW`, and `x-default`.
- English entry routes run `assets/locale-router.js` before first paint. A first
  visit from any `zh` browser locale routes to Traditional Chinese. Manual
  language selection is persisted as `rk-locale` and takes priority on later
  visits.

## Shared shell contract

Header, desktop navigation, full-screen mobile navigation, display controls,
and footer are generated by `scripts/sync-yomi-shell.mjs`. Never edit content
between `YOMI_SHELL` markers by hand.

After changing the renderer, regenerate and audit:

```sh
node scripts/sync-yomi-shell.mjs
node scripts/sync-yomi-home-locale.mjs
node scripts/sync-yomi-shell.mjs
node scripts/sync-yomi-home-locale.mjs --check
node scripts/sync-yomi-shell.mjs --check
node scripts/audit-yomi-site.mjs
```

`assets/theme-init.js` applies persisted display preferences before first paint.
`assets/ui.js` owns controls, reveal effects, and accessible mobile navigation.
`assets/yomi-release.js` owns volatile release metadata.

The `yomi-site-audit` workflow prevents generated shell drift, missing SEO
contracts, duplicate shell regions, and accidental client-side language swaps
inside localized guide documents. It also compares the semantic tag, class,
and section-id structure of both guide routes so translations cannot silently
develop a different page architecture.
