LINE × Model Context Protocol

LINE MCP 是什麼？
讓 AI 讀取與回覆個人 LINE

LINE MCP server 把 Claude 等 AI agent 連接到 LINE，但「連到哪一種 LINE」非常重要：官方帳號、桌面 App，或你正在使用的個人帳號，是三種不同問題。

先講結論：如果你要操作 LINE Official Account，選官方 Bot MCP；如果你要讓本機 AI 讀取、搜尋並回覆自己既有的個人 LINE 對話，Yomi 才是針對這個需求設計。

比較

LINE MCP 的三種做法

做法連接對象適合需求主要限制
LINE 官方 Bot MCPLINE Official Account客服、通知、品牌機器人、Messaging API 工作流不是使用者個人帳號的既有聊天
LINE Desktop 自動化桌面版 LINE 介面利用 UI 操作既有桌面應用程式依賴視窗與介面狀態，實作品質各異
Yomi 個人 LINE MCP自己的個人 LINE 帳號讀取、回覆、搜尋既有對話與本機 E2EE 處理非官方；次要裝置不保證取得全部舊歷史

Yomi 如何連接個人 LINE？

01 · LOGIN

以次要裝置登入

Yomi 登入你自己的 LINE 帳號，不需要建立 bot 帳號、channel access token 或 webhook。

02 · PROTOCOL

直接處理 LINE 協定

它不是在螢幕上找按鈕，而是以本機 MCP server 向 AI agent 提供明確工具。

03 · E2EE

本機解密 Letter Sealing

可取得的 E2EE 訊息與媒體在你的裝置上解密；搜尋索引也保留在本機。

04 · MCP

交給 Claude 或其他 agent

AI 可以讀取未讀摘要、搜尋對話、回覆、傳送媒體，並找出正在等你回覆的對話。

什麼情況適合使用 Yomi？

  • • 想讓 Claude 整理自己 LINE 帳號的未讀訊息。
  • • 想跨群組與一對一聊天搜尋過去討論。
  • • 想由 AI 協助回覆、傳圖、標註成員或處理已讀。
  • • 希望訊息解密、索引與語意搜尋留在本機。

使用前必須知道的限制

Yomi 是獨立的非官方開源專案，與 LINE 沒有關聯或背書。使用額外用戶端可能違反 LINE 服務條款，並帶來限流或帳號停權風險。

此外，LINE 不一定會把較舊的一對一歷史或已輪替的群組加密金鑰提供給次要裝置。Yomi 會明確回報缺少解密材料，不會捏造無法讀取的內容。
